  NÍVEL 1: FILTRAGEM VISUAL (Client-side)
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Usuário acessa home.php
        ↓
  home.php carrega menu-access.js
        ↓
  DOMContentLoaded → initMenuAccess()
        ↓
  Fetch GET /admin/api/getPerfis.php
        ↓
  API retorna: {success, perfis: [...], usuario_id}
        ↓
  JavaScript filtra menu:
  • Encontra `.menu-header-text` (seções)
  • Oculta seções não permitidas (display: none)
  • Usuário vê apenas menu do seu perfil


  NÍVEL 2: VALIDAÇÃO DE ACESSO (Server-side)
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Usuário clica item de menu
        ↓
  Chama: carregarPagina('nomedapagina')
        ↓
  Abre: frame.php?page=nomedapagina
        ↓
  frame.php valida:
  1. Token e sessão (401 se inválido)
  2. Página existe no whitelist (404 se não)
  3. Usuário tem perfil para seção (403 se não)
        ↓
  SE PERMITIDO: Carrega página (200)
  SE NEGADO:   Retorna erro 403

  ┌──────────────┬─────────────────────────────────────────────────────┐
  │ COLUNA       │ TIPO        │ DESCRIÇÃO                             │
  ├──────────────┼─────────────┼─────────────────────────────────────────┤
  │ id_usu_perfil│ INT PRIMARY │ ID único da relação                   │
  │ usuario      │ INT FK      │ Referência para usuarios(id_usuario)  │
  │ perfil       │ VARCHAR(20) │ Tipo: ESTUDANTE, SERVIDOR, ADMIN     │
  └──────────────┴─────────────┴─────────────────────────────────────────┘

  CONSTRAINTS:
  • FOREIGN KEY (usuario) → usuarios(id_usuario)
  • UNIQUE KEY (usuario, perfil) ← Um perfil por usuário
  • CHECK (perfil IN ('ESTUDANTE', 'SERVIDOR', 'ADMIN'))

  EXEMPLO DE DADOS:
  
  id_usu_perfil │ usuario │ perfil

  2             │ 2       │ SERVIDOR
